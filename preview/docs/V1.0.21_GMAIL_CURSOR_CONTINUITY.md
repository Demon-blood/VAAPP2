# v1.0.21 — Gmail Cursor Continuity & Watch Renewal Integrity

## Problem closed

Gmail `users.watch` returns the mailbox's **current** history record. That value is useful as watch metadata, but it is not proof that VAAPP has consumed every mailbox change up to that point. Before v1.0.21, watch renewal wrote that value directly into the durable `GmailMailboxState.history_id`. The periodic `gmail.sync` fallback also performed a bounded mailbox scan and then advanced the cursor from the current Gmail profile.

Either path could move the processing cursor ahead of work that had not been consumed yet. A later `history.list(startHistoryId=...)` would then start after the advanced cursor, creating a silent mail-loss window.

## v1.0.21 behavior

- Watch renewal records topic and expiration without changing the durable processing cursor.
- The watch response `historyId` is exposed separately as `watch_history_id`; `history_id` continues to mean the last consumed processing cursor.
- Profile refresh is observational by default. Advancing the processing cursor now requires an explicit opt-in from a caller that has independently completed the corresponding scan.
- A full recovery captures Gmail's current history ID **before** the bounded recovery scan, completes that scan, checkpoints the pre-scan ID, and then consumes history after that ID. Mail that arrives while the scan is running is therefore caught by the history phase rather than skipped.
- The scheduled `gmail.sync` job uses `history_sync` whenever a durable cursor already exists. This makes periodic polling a lossless fallback for delayed or missed Pub/Sub notifications instead of a cursor-jumping full scan.
- Gmail history pagination must reach the end of the provider cursor chain. If a defensive page ceiling is reached while `nextPageToken` still exists, the job fails closed and leaves the stored cursor unchanged.
- `users.watch` executes off the asyncio event loop and is attempted once at the provider-operation boundary. Workflow retry may renew the watch again, but no retry can advance the processing cursor.

## Human-boundary integrity

This change creates no new Needs You path. Provider/network delay, watch renewal uncertainty, and incomplete history pagination remain VA-owned operational conditions. Existing Google reauthorization/consent boundaries remain the genuine human boundary.
