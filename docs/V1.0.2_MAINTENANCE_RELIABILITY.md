# Full-Time VA v1.0.2 — Maintenance Reliability

v1.0.2 is a maintenance rollup on the verified v1.0.1 baseline. It fixes the real Android/PostgreSQL communication-sync failure and hardens fulfillment configuration and order classification without weakening executor or verification policy.

## Phone-sync reliability

- Normalize offset-aware Android RFC3339 timestamps to naive UTC before writing existing timezone-naive communication columns.
- Isolate failed records inside communication batches so one malformed SMS/call does not turn an entire history sync into HTTP 500.
- Preserve the encrypted Android pending-event queue when any backend record fails and surface bounded failure diagnostics to the paired device.

## Editable provider configuration

- Fulfillment providers are editable rather than add-only. Existing stable slugs are preserved while name, provider type, Personal/Pro scope, enabled state, support phone and recipe can be changed.
- Provider portal linking uses the actual configured Secure Browser portal names instead of requiring a numeric database ID. Only same-scope portals are selectable.
- Secure Browser portals are editable from Work → Portals. URL/allowlist/scope/enabled state can change; blank replacement login fields keep existing encrypted credentials.

## Order hygiene

- An `OrderRecord` is not automatically a logistics objective. Fulfillment requires source-backed order/shipping/delivery/pickup/tracking evidence.
- Google payment/app-store receipts, GPA-style payment identifiers and generic payment/receipt records without fulfillment evidence are classified as non-fulfillment.
- Existing false-positive fulfillment objectives are dismissed during reconciliation/read and excluded from normal Fulfillment/Orders lists.
- The user can explicitly choose **Not an order** from Work → Orders or a linked Fulfillment objective. This only changes order/logistics classification; the original Gmail and financial receipt evidence remains preserved.
- A dismissed order can be restored through the backend if it was corrected in error.

## Evidence contract

Configuration, ingestion, dispatch and browser navigation are not completion evidence. External objectives still complete only after their required source/provider postcondition is independently observed.
