# v0.7.0 Gmail Inbox attention hotfix

## Symptom

Gmail showed VA labels, especially `Mail/00 Status/Belangrijk bewaren`, while routine
messages remained in the main Inbox. The screen recording supplied during validation
showed this across promotions, service notifications, account confirmations and routine
operational messages.

## Root cause

The v0.7.0 policy conflated `preserve=True` with `protected=True`, and then treated every
protected message as needing to remain in Inbox. Historical AI decisions that had set
`preserve=True` broadly therefore became permanent Inbox pins. The first v0.7.0
reconciliation reused those stored decisions, so it could not repair them.

## Corrected semantics

- `preserve`: retain the message and never auto-trash it. It does **not** pin Inbox.
- `archive`: remove Gmail's `INBOX` label when no unresolved attention remains.
- Inbox attention: action required, high/urgent priority, approval-gated task, or pending reply.
- protected legal/security/finance/family/medical content may be preserved **and archived**.
- confidently low-value newsletter/promotion/social/notification decisions clear stale
  `preserve=True`, allowing delayed safe Trash cleanup.
- unread mail is still never auto-trashed.

## Existing mailbox repair

The reconciliation marker is advanced to `v070_gmail_attention_policy_reconciled_v2`, so
the next Gmail sync runs a fresh Inbox pass even if the original v0.7.0 reconciliation
already completed. It removes `INBOX` from safely filed messages and removes stale
`Mail/00 Status/Belangrijk bewaren` / `Mail/00 Status/Actie nodig` labels where the stored
decision no longer warrants them.

## Gmail label mutation hardening

`modify_gmail_message()` now resolves custom display-name labels to immutable Gmail label
IDs before removal. System IDs such as `INBOX` continue to be passed directly. Missing
custom labels are skipped rather than created solely for removal.

## Safety invariants

- no historical message is moved directly to Trash by reconciliation;
- high/urgent/actionable/reply-pending messages stay in Inbox;
- protected content is retained even when archived;
- low-value Trash cleanup remains delayed and read-only;
- no new AI call is needed for the historical Inbox repair.
