# v1.0.15 — Generic Browser Late-Evidence Recovery & Objective Continuity

## Defect

v1.0.11 made non-replay-safe browser operations duplicate-safe: once a provider-side side effect may have happened, the durable side-effect marker forces later execution into provider-postcondition verification before any original recipe step can run again.

Generic Autonomous Core browser objectives did not preserve that continuity. When their linked `BrowserOperation` became `creation_uncertain`, both dispatch and verification paths marked the objective step `failed`, set `finished_at`, and moved the objective to `blocked_system`. Document/form ownership also projected the same uncertainty as `blocked_system`.

The provider mutation was therefore protected from duplicate replay, but late provider evidence could be abandoned because the generic verification step was no longer eligible for `verify_ready_steps`.

## v1.0.15 contract

- A `creation_uncertain` generic browser operation is resumable only when the existing v1.0.11 durable side-effect marker proves postcondition-only reconciliation is safe.
- The same `BrowserOperation` is resumed; no second operation or business idempotency key is created.
- The browser runtime still verifies the declared provider postcondition before any original recipe step.
- Safe uncertainty keeps the VA objective step in `verifying`, clears `finished_at`, and keeps the objective VA-owned in `verifying`.
- Historical failed browser-verification steps are reopened automatically when their existing operation is still `creation_uncertain` and has the durable side-effect marker.
- Markerless uncertainty remains `blocked_system`; v1.0.15 does not invent replay safety.
- Genuine portal authentication remains `needs_user`.
- Definitive browser failure remains `blocked_system`.
- Document/form obligations project active browser uncertainty as `in_progress`, while retaining the provider error text for diagnostics. They complete only when the linked browser operation is independently `verified`.
- No database migration is required.

## Safety invariant

> An ambiguous generic browser side effect remains provider-reconciliation-owned and never becomes replay permission or fake user work.
