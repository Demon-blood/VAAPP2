# v1.0.16 — Device Communication Dispatch Claim & Late-Evidence Continuity

v1.0.16 hardens Android-originated communication side effects, especially background SMS replies.

## Defect closed

Before v1.0.16, a device action remained `pending` on the backend until Android reported a carrier or RemoteInput result. Android had a local at-most-once marker, but the server did not durably know that dispatch had started. A lost callback plus app-data loss or another paired device could therefore expose the same pending action again. Separately, the Autonomous Core terminalized an old `pending` action after 30 minutes, so later valid device evidence could not finish the original objective automatically.

## v1.0.16 behavior

- Android must atomically claim a backend action before SMS carrier or supported RemoteInput dispatch.
- Only the first `pending -> dispatching` claim creates ownership. Repeated claims by that same paired device are idempotent, so a lost claim response can be recovered; another device is denied.
- `dispatching` SMS actions remain visible for reconciliation and same-device claim recovery. A different device cannot resume them, and a resend still requires the original local execution marker to prove no prior send occurred.
- Android re-posts SMS carrier handoff evidence before generic stored failure evidence, preserving the stronger successful-send fact if a later delivery callback failed while offline; non-SMS stored evidence remains reconciliation-only.
- Android persists its local `action_done_<id>` marker synchronously before `SmsManager` is invoked, so same-device claim recovery cannot replay a send that already crossed the local boundary.
- Definitive pre-handoff, single-part SmsManager, and RemoteInput failures are stored locally when the backend callback is unavailable, then re-posted so the existing safe retry path can proceed. Multipart send failure is conservatively `creation_uncertain` because other segments may already have crossed the carrier boundary.
- Missing device evidence no longer becomes terminal merely because 30 minutes elapsed.
- Verification backs off as uncertainty ages while the same durable action remains VA-owned.
- Historical steps failed by the old 30-minute cutoff are reopened only when the linked action is not definitively failed/cancelled.
- Late `sms_sent`, `sms_delivered`, or RemoteInput evidence completes the same objective; no replacement action is created.
- Definitive carrier/device failure remains system-owned and does not become fake Needs You work.

## Safety invariant

Missing evidence after a durable backend dispatch claim never authorizes replay. Claim-response loss can be recovered only by the same paired device and only while its synchronously persisted local execution marker still proves the provider send has not happened. A different device is denied; elapsed time alone never authorizes retry.
