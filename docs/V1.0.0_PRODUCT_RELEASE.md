## Compatibility contract

`backend/app/core/version.py` defines the backend release and minimum Android semantic release as `1.0.0`.

Android defines `appRelease` and `minimumBackendVersion` once in `android/lib/release_contract.dart`. AppState compatibility warnings, Product Status, onboarding repair/deployment flow, and Render health verification all consume that shared contract.

A repaired/new Render deployment must expose both `/health` and `/api/system/info` and report backend `1.0.0` or newer before the phone continues to pairing. The legacy `0.4.16` deployment floor is removed.

## Product Status

The Android **Product Status** workspace is an operational/readiness view, not a synthetic success screen. It reports:

- Android/backend release compatibility;
- whether continuous automation is enabled;
- Autopilot health and recoverable exceptions;
- endpoint failures;
- the current Needs You count;
- capability rows whose real executor is currently available;
- capability/setup gaps and their resolution class.

A missing provider or executor is a setup/capability gap. It is not a completed objective and is not silently converted into a user task unless the underlying blocker is genuinely user-resolvable authentication or a material decision.

## External completion evidence

The v1.0 rule remains:

`provider/source postcondition evidence -> domain verification -> objective completion`

The following are **not** sufficient completion evidence by themselves:

- a configured provider;
- a UI success snackbar;
- a browser click or submitted form intent;
- a placed or provider-completed phone call;
- an initiated payment or transfer;
- a queued email/SMS/message;
- a local workflow state without downstream provider/source confirmation.

Ambiguous provider outcomes remain quarantined and are reconciled before retry. Blind duplicate external execution is not allowed.

## Release validation

The v1.0 contract tests cover semantic release identity, Android/backend compatibility alignment, phone deployment version verification, Product Status wiring, and the continued Phase-8/9 executor/evidence contracts. GitHub CI remains the authoritative final backend + Flutter + Android release gate.
