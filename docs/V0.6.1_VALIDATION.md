## Environment-limited gates

The packaging sandbox does not contain `aiosqlite`, APScheduler, Google API client dependencies, Ruff, Flutter, or Dart, and package-network installation is unavailable. For that reason the complete database-backed pytest suite, Ruff, `flutter analyze`, `flutter test`, signed APK build, and release publication were not claimed as locally executed.

The included GitHub Actions release workflow installs `backend[dev]`, runs Python compilation, Ruff, the complete backend test suite with the required settings environment, installs the pinned Flutter 3.38.7 SDK, runs Flutter analysis/tests, builds the signed release APK, hashes it, and publishes it only if all preceding gates succeed.

## Safety invariants checked in implementation

- No automatic bypass of OAuth, SCA/Itsme, bank authorization or security challenges.
- No automatic learning for security, credential, bank/payment authorization or legal preference domains.
- Financial/legal/security/identity/medical reply contexts remain human-gated even when a sender preference exists.
- Automatic dead-letter recovery is restricted to classified transient failures and has a bounded recovery budget.
- Payment initiation has one durable path through `bill.lifecycle`; scheduled banking synchronization does not initiate a second parallel payment path.
- Existing creditor/IBAN approval, amount limits, account scope, balance and safety reserve controls remain in the bill lifecycle.
- v0.5.1 paid-receipt/nonpayable protections and v0.5.2 Gmail conflict recovery remain present.
