# Full-Time VA v0.7.1 — Historical Finance Learning

## Purpose

v0.7.1 lets Financial Autopilot bootstrap a budget from prior bank statements while keeping Enable Banking as the authoritative ongoing bank feed. Imported statements are historical evidence, not synthetic live-bank transactions.

## Android flow

Open **Money → Budget → Import financial history**, choose Personal or Pro as a fallback ownership scope, and select up to 12 PDF statements. When an imported statement IBAN matches an already connected account, that account and its scope win automatically.

The Budget page shows the imported period, statement/transaction count, matches to Enable Banking, historical-only rows, internal transfers excluded from spending, and statement-chain verification. Budget envelopes left at `0` continue to use learned values; explicit user limits always override learned values.

## Beobank GO parser

Beobank GO statements are parsed from their native PDF text. The importer extracts statement/account identity, statement dates, opening/closing balances, credits/debits, transaction sequence, booking/value dates, transaction type, amount/direction, counterparty/IBAN, remittance, card occurrence timestamps and foreign-currency/fee metadata where present. OCR is not used for this format.

A Beobank statement is rejected unless all of these are true:

- transaction numbering is complete;
- extracted credit total equals the statement credit total;
- extracted debit total equals the statement debit total;
- opening balance + credits - debits equals the closing balance to the cent.

Consecutive imported statements for one IBAN also expose whether each next opening balance equals the previous closing balance.

## Cross-source reconciliation

Historical rows are stored in `historical_financial_transactions`. They are reconciled against Enable Banking using account, direction, exact amount, date proximity and available counterparty/IBAN/reference evidence. A matched statement row is excluded from learned spending/income so the same money event is never counted twice. Matching is deliberately conservative when several equal-value transactions exist.

## Budget classification

The v0.7.1 deterministic category policy distinguishes digital purchases from recurring subscriptions. Irregular Google Play purchases map to `digital`; recurring services such as Netflix and OpenAI can map to `subscriptions`. Own-account transfers are excluded. A Beobank Revolut card top-up is treated as internal only when a connected Revolut account actually exists.

Income is classified separately as salary, holiday pay, bonus, benefit, tax refund, refund, irregular income, or internal transfer. This prevents one-off inflows from silently becoming assumed recurring salary.

## Scope and role

Ownership scope is only `personal` or `pro`. Financial purpose is a separate account role (`operating`, `savings`, `reserve`, `tax`, `income`, `disabled`). On upgrade, a legacy account stored with scope `reserve` is converted to Personal ownership plus the reserve role.

## Documents

The retention policy now rejects branded/localized website boilerplate such as `*-terms-en.pdf`, `*-conditions-fr.pdf`, algemene voorwaarden, conditions générales, privacy/cookie policies, while preserving invoices, statements, signed contracts and other durable records. Extracted PDF text is used as supporting evidence, and retained documents are categorized from the document itself rather than blindly inheriting the parent email category.
