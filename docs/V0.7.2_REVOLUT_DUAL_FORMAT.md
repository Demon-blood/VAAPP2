# Full-Time VA v0.7.2 - Revolut dual-format import

## Import policy

Financial history accepts Beobank PDF statements and Revolut XLSX/PDF exports.

For Revolut, XLSX is the authoritative ledger when both formats are supplied. The PDF is an enrichment and validation source. The two files are deliberately merged into one primary-account statement rather than stored as two monetary histories.

## XLSX semantics

The parser requires the Revolut columns:

`Type`, `Product`, `Started Date`, `Completed Date`, `Description`, `Amount`, `Fee`, `Currency`, `State`, `Balance`.

Only `COMPLETED` rows enter historical financial evidence. `REVERTED` rows are recorded only as ignored-count validation metadata.

The account cash delta is `Amount - Fee`. This is required because plan fees and some transfer fees are represented separately from Amount, while fee refunds can be negative fees.

Every completed row is checked against the running balance. An unreconciled workbook is rejected and cannot influence Financial Autopilot.

## PDF semantics

The Revolut PDF parser validates each account section against the statement balance summary. It uses running-balance movement to determine debit/credit direction and can enrich transactions with transaction IDs, counterparty/reference text, card details, fee information, and foreign-currency metadata.

Additional account sections that are not present in the XLSX are retained as separate historical account evidence. They are not silently attached to the primary connected Revolut account unless an exact account identity can be established.

## Cross-source deduplication

A paired XLSX and PDF for the same primary account use the same canonical statement identity. If XLSX already exists, PDF enriches its transaction rows. If PDF arrived first, a later XLSX replaces only the authoritative cash/status fields while preserving PDF enrichment.

Historical evidence that matches an Enable Banking transaction remains excluded from learned-spending totals so one monetary event is counted once.

## Own-account transfers

The importer recognizes Revolut FX pocket movements and Robo portfolio movements as internal. It also performs narrow cross-statement confirmation for Beobank card debits to Revolut versus Revolut top-up credits using amount, currency, scope, and date proximity. Confirmed pairs are excluded from both spending and income.

When confirmed historical internal evidence has already matched an Enable Banking row, the live row inherits `internal_transfer` as well.

## Refunds

Refund evidence is not treated as income for budgeting. Refund credits reduce the corresponding learned spending category.

## Privacy and fixtures

The repository contains only synthetic bank-statement fixtures. Real statements, real names, addresses, IBANs, transaction IDs, and user balances are not packaged in source or CI fixtures.
