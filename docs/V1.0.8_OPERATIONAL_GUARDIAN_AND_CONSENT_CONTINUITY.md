# v1.0.8 — Operational Guardian & Consent Continuity

v1.0.8 hardens the Full-Time VA against avoidable operational interruptions. It adds a periodic operational guardian that distinguishes recoverable system work from genuine provider/account-holder boundaries.

## Product contract

The guardian must never manufacture user work for a condition VAAPP can recover itself. System recovery remains VA-owned. `needs_user` is created only when current provider state proves that fresh human participation is required.

Operational continuity is not completion evidence. A continuity objective closes only when current provider state proves that the blocker has been removed.

## Consent continuity

- Active bank consents are watched for expiry. Inside seven days the VA creates one durable continuity objective; inside 48 hours it becomes high priority. Renewal remains a genuine account-holder/provider authorization boundary.
- OAuth access-token expiry does **not** create user work when a refresh credential exists. If an enabled OAuth connection is close to expiry and no refresh credential exists, the VA creates a genuine reconnect objective.
- A renewal/reconnect objective is marked `completed` only after persisted provider state shows a renewed validity window or refresh capability, and a `provider_state` evidence row is stored.

## Workflow self-healing

The guardian checks the cadence of the autonomous core, Gmail sync, Calendar sync, Banking Autopilot and provider-health work. A missing cadence may be safely re-enqueued only when the previous row completed or no row exists. Stuck, retrying or dead-letter work is not duplicated; the existing watchdog/recovery classifier continues to own those states.

## Payment monitoring

Recent provider payment rejections are counted in reliability health. v1.0.8 does not reinterpret every rejection as user work; existing payment authorization and reconciliation flows remain authoritative.

## Android

Work → Operations shows an **Operational continuity** section summarizing consent continuity, system recovery and recent payment rejection signals. The section explicitly states that system recovery stays VA-owned.

## Deliberate boundary

Database-backup health is not claimed as verified because VAAPP does not currently have a configured backup-provider telemetry source. Production backup monitoring remains an external deployment requirement until such a source is wired into the product.
