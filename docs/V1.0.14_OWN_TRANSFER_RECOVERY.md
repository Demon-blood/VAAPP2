# v1.0.14 — Own-Account Transfer Recovery & Human Boundary Integrity

v1.0.14 closes the remaining provider-creation ambiguity gap in Financial Autopilot own-account transfers.

## Problem

A network timeout or a nominally successful Enable Banking response without a provider payment ID may mean the transfer was already created. v1.0.13 correctly suppressed a blind duplicate retry, but it incorrectly converted that system/provider uncertainty into user work by setting `requires_user_action` and creating an urgent `bank_transfer_uncertain` approval task. The refresh path also refused to reconcile a transfer whose provider payment ID was missing.

## Recovery contract

- Creation uncertainty remains VA-owned and `requires_user_action` stays false.
- An authorization URL is never exposed unless it is bound to a real provider payment ID.
- The same idempotency key remains active, so Financial Autopilot cannot create a second transfer intent for the same planned movement.
- VAAPP checks the source account's booked provider transactions instead of retrying payment creation.
- Recovery requires the same source account, debit direction, exact amount, currency, exact destination IBAN, booking date within four days of the original intent, a provider transaction ID, and exactly one matching candidate.
- One unique candidate completes the existing transfer from independent booked-bank evidence.
- Zero candidates remain `waiting_for_evidence`; multiple candidates remain `ambiguous`.
- Zero/multiple/provider-unavailable outcomes stay VA-owned and never create Needs You work.
- Historical `bank_transfer_uncertain` tasks are closed automatically when the transfer enters the new reconciliation path.
- Genuine bank authorization remains unchanged when a real provider payment ID and authorization URL are present.
- No database migration is required.

## Safety invariant

> An uncertain own-account transfer is never recreated merely because its provider creation response was lost, and it is never assigned to the user merely because VAAPP lacks provider confirmation.
