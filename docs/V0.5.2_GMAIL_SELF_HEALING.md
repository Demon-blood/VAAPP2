# v0.5.2 Gmail self-healing

## Problem observed

The Today screen could show Autopilot as degraded with many `gmail.sync` jobs in `retry` and `dead_letter`, plus repeated identical `Autopilot failed: gmail.sync` items.

The v0.5.1 Gmail label helper used a non-atomic sequence:

1. list labels;
2. decide the label is absent;
3. create the label.

A concurrent worker or overlapping Gmail operation could make step 3 conflict with state that changed after step 1. The resulting HTTP 409 escaped the Gmail operation and caused the durable workflow engine to retry the entire Gmail sync.

Every exhausted scheduled Gmail job then became a separate dead-letter row, and Daily Briefing surfaced every dead letter as a separate `Needs you` item.

## v0.5.2 correction

### Gmail operation boundary

`google_api.py` now:

- executes Gmail mutations through a bounded async wrapper;
- retries HTTP 409/429 and transient 5xx responses at the individual request boundary;
- handles a label-create 409 by re-listing labels and adopting the label created by the competing worker;
- resolves a batch of labels from one initial label-list call.

### Durable failure compaction

The workflow engine derives a stable failure signature. Repeated `gmail.sync` HTTP 409 dead letters share one signature even if their request URLs contain different message or label identifiers.

Only the newest active representative remains `dead_letter`; older identical failures become `superseded`. The rows and original errors remain in PostgreSQL for auditability.

### One-time legacy repair

At the first v0.5.2 startup, all existing `gmail.sync` jobs in `retry` or `dead_letter` whose stored error contains `HttpError 409` are marked `superseded`.

The migration records `v052_gmail_conflict_backlog_repaired` in `audit_logs`. If the server restarts again, the migration does not suppress any new 409 failures created after the upgrade.

### Recovery endpoint

`POST /api/autopilot/recover`:

1. compacts duplicate dead letters;
2. requeues one active representative per remaining failure;
3. resets attempts for those representatives.

The Android Today status button calls this endpoint.

## Data safety

No workflow row is deleted. `superseded` is an inactive terminal status used to keep obsolete duplicate attempts available for audit inspection without counting them as current failures.

No Gmail message, OAuth token, payment, bill, receipt, bank account, document or connector record is removed by this release.
