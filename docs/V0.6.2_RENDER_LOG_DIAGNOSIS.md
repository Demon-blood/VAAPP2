# v0.6.2 Render log diagnosis — 2026-08-10

The supplied Render log shows that v0.6.1 built and deployed successfully. Uvicorn completed application startup and `/health` returned HTTP 200. The actionable faults were runtime hardening issues rather than a failed Render deployment.

## 1. Gmail label creation HTTP 409

Observed failure:

`HttpError 409 ... "Label name exists or conflicts"`

The failure originated in `ensure_gmail_labels()` while processing a durable `gmail.sync` job. v0.6.1 already re-listed labels after a conflict, but it required the winning label to become visible with an exact display-name match. v0.6.2 performs normalized reconciliation, does not repeat the conflicting create POST, and degrades an unresolved cosmetic label instead of aborting the mailbox sync.

A one-time startup repair supersedes pre-v0.6.2 retry/dead-letter Gmail jobs with the exact label-conflict error. The scheduler then immediately enqueues a fresh Gmail sync using the corrected resolver.

## 2. Scheduler missed by exactly two hours

Observed warning:

`housekeeping_enqueue_job ... was missed by 2:00:00`

The scheduler timezone is Europe/Brussels, while startup passed a naive `datetime.now()`. On Render the process clock is UTC, and on 2026-08-10 Brussels is CEST (UTC+2), producing the exact two-hour misfire. v0.6.2 passes a timezone-aware Brussels timestamp to APScheduler for immediate startup runs.

## 3. PyMuPDF import warning

Observed warning:

`The fitz API is deprecated ... Use import pymupdf instead.`

The PDF processor now imports `pymupdf as fitz`, retaining the existing call sites while using the current package namespace.
